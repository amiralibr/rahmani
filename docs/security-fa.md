# وضعیت امنیت — نگاشت به OWASP Top 10 (2021) و ASVS

> این سند صادقانه می‌گوید چه چیزی پیاده شده و چه چیزی نه. «پیاده شده» یعنی در کد وجود دارد و در پیش‌نمایش محلی تست شده است. ممیزی بیرونی جایگزین این موارد نیست.

| شناسه | کنترل | وضعیت |
|---|---|---|
| A01 کنترل دسترسی | نقش‌های RBAC (`manager/reception/specialist/viewer`) + `SpecialistGuard`/`ManagerGuard`/`ReceptionGuard`؛ نوشتن پذیرش فقط برای `reception`؛ تغییر حساب مدیر ممنوع؛ جداسازی پیشنهاد/تأیید بازپرداخت (یک نفر نمی‌تواند هر دو باشد) | پیاده شده |
| A01 | حساب مراجع فقط با کوکی httpOnly؛ بدون فهرست عمومی کاربران | پیاده شده |
| A02 رمزنگاری | گذرواژه‌ها با scrypt (salt تصادفی ۱۶ بایتی)؛ نشست‌ها با هش sha256 در DB؛ MFA اجباری (TOTP) برای کارکنان؛ کلید MFA با `STAFF_MFA_KEY` رمز شده؛ تراکنش‌های پرداخت فقط سمت سرور تأیید می‌شوند | پیاده شده |
| A02 | **پروندهٔ بالینی:** جدول‌ها در schema جدا (`clinical`)، متن‌ها با AES-256-GCM و کلید مستقل `CLINICAL_KEY` رمز می‌شوند؛ فقط نقش `specialist`؛ لاگ دسترسی کامل؛ بدون کلید، ماژول 503 برمی‌گرداند و سایت عمومی سالم می‌ماند | پیاده شده |
| A02 | TLS در انتقال فقط با راه‌اندازی nginx + گواهی (خارج از این مخزن)؛ HSTS فقط هنگام `PUBLIC_ORIGIN=https` ارسال می‌شود | نیازمند زیرساخت |
| A03 تزریق | همهٔ پرس‌وجوها پارامتری (`$1…`)؛ TypeORM خام بدون واسطهٔ string-concat | پیاده شده |
| A03 | اعتبارسنجی ورودی با class-validator + `whitelist/forbidNonWhitelisted`؛ بدنهٔ پیش‌فرض 4kb | پیاده شده |
| A04 طراحی ناامن | نگه‌داری وقت با تراکنش + exclusion constraint (نبود رزرو تکراری)؛ رسید نقدی/بازپرداخت در یک تراکنش تأیید می‌شود؛ منابع با `Cache-Control: no-store` | پیاده شده |
| A05 پیکربندی | سربرگ‌های امن در `security.ts`: CSP (بدون `upgrade-insecure-requests` مگر در HTTPS)، `X-Content-Type-Options`، `X-Frame-Options`/`frame-ancestors 'none'`، `Referrer-Policy`، `Permissions-Policy`، `COOP`/`CORP`، حذف `X-Powered-By`؛ `/account/`، `/reception/`، `/api/` در robots بسته؛ صفحه‌های خصوصی `noindex` | پیاده شده |
| A06 مؤلفه‌ها | وابستگی‌ها با `npm audit` بررسی می‌شوند؛ نیویورک تجربی نگذارید؛ `npm audit --production` را قبل از انتشار اجرا کنید | نیازمند اجرای ادواری |
| A07 هویت و احراز | محدودیت نرخ روی ورود/ثبت‌نام/بازنشانی (۱۲–۱۵ دقیقه‌ای)، ثبت درخواست (۱۵/۱۵دقیقه)، staff login (۱۰/۱۵دقیقه)؛ تأیید TOTP قبل از صدور نشست؛ نشست مراجع ۱ ساعته، کارکنان با انقضای DB | پیاده شده |
| A08 سلامت نرم‌افزار | دیپلوی از `main` با build محلی؛ no عقدهٔ خارجی در runtime (فرانت استاتیک + Jitsi با `noopener` در تب جدید) | پیاده شده |
| A09 ثبت رویداد | تاریخچهٔ وضعیت درخواست‌ها (`contact_history`)، رویداد حضور، رسیدهای مالی با ثبت‌کنندهٔ ذخیره شده؛ لاگ اپلیکیشن `error/warn` | ناقص: لاگ متمرکز/هشدار هنوز نیست. پیش از انتشار: uptime + جمع‌آوری لاگ راه‌اندازی کنید |
| A10 SSRF | فقط endpoint پرداخت زرین‌پال با allowlist میزبان و timeout ۸ ثانیه؛ ورودی کاربر هرگز به URL تبدیل نمی‌شود | پیاده شده |
| حریم خصوصی | نام‌های مستعار برای مراجع؛ هیچ دادهٔ بالینی در CRM/لاگ/جدول رزرو نیست؛ یادداشت ژورنال پیش از انتشار بررسی می‌شود؛ صفحه‌های خصوصی `noindex` | پیاده شده |
| CSP | با استاتیک‌بودن خروجی Next، اسکریپت‌های inline رندر می‌شوند؛ بنابراین `script-src 'unsafe-inline'` اجتناب‌ناپذیر است؛ بقیهٔ directives محدود هستند | قابل بهبود با nonce در مهاجرت بعدی |

## محدودیت‌های اعلام‌شده (هنوز پیاده نشده‌اند)
1. **پروندهٔ بالینی رمزگذاری‌شده** پیاده شده است (schema جدا، AES-256-GCM، فقط specialist، audit لاگ). باقی‌مانده: چرخش کلید `CLINICAL_KEY` (re-encrypt)، سیاست نگهداری/حذف پرونده (retention)، و ASVS ممیزی‌شده. تا نهایی شدن retention claim «انطباق کامل» نکنید.
2. **درگاه پیامک/ایمیل** — عملاً غیرفعال است؛ متن‌ها «پیش‌نمایش» اعلام می‌کنند.
3. **پرداخت واقعی** — فقط با `ZARINPAL_MERCHANT_ID` و `PUBLIC_ORIGIN` معتبر فعال می‌شود؛ بدون آن دکمهٔ پرداخت فعال نمی‌شود.
4. **تست نفوذ بیرونی و ASVS Level 1 ممیزی‌شده** — باید قرارداد شود؛ این سند فقط فهرست خود-ارزیابی است.
5. **پشتیبان و بازیابی** — `docs/vps-backup-fa.md`؛ RPO/RTO هدف ۱ ساعت/۴ ساعت هنوز تأیید نشده‌اند.
6. **مانیتورینگ و پاسخ به حادثه** — مالک و runbook مشخص نیست؛ قبل از دادهٔ واقعی تعیین شود.
