# راهنمای مدیر سامانه — مرکز رحمانی

> این راهنما برای مدیر فنی/پذیرش ارشد نوشته شده است. هیچ مجوز، تاریخ یا تأییدی در سامانه درج نشده است مگر آن‌که مرکز آن را در پنل ثبت کند.

## نقش‌ها
| نقش | دسترسی |
|---|---|
| `manager` | خواندن همهٔ پنل‌ها و آمار تجمعی؛ مدیریت حساب کارکنان (فعال/غیرفعال)؛ تغییر تنظیمات عمومی سایت؛ بازبینی ژورنال |
| `reception` | صف درخواست‌ها، حضور، جلسات، بازپرداخت (با جداسازی وظایف)، ثبت **پرداخت نقدی**، صف شکایت و بازخورد، ظرفیت‌ها و تقویم، انتشار زمان‌ها |
| `specialist` | فقط زمان‌بندی و درآمد خودش (خواندنی) |
| `viewer` | خواندنی پذیرش؛ بدون تغییر |

## ساخت و مدیریت حساب کارکنان (روی خود سرور)
ابزار `staff-cli` اجرا می‌شود و گذرواژه/کلید MFA را **یک‌بار** چاپ می‌کند؛ آن را امن تحویل دهید و جایی ذخیره نکنید:
```bash
cd apps/api
# STAFF_MFA_KEY، PGPASSWORD، PGDATABASE، PGPORT باید تنظیم باشند
node dist/staff-cli.js create  نام‌کاربری  reception|specialist|viewer|manager
node dist/staff-cli.js disable نام‌کاربری          # همهٔ نشست‌ها هم حذف می‌شوند
node dist/staff-cli.js reset-password نام‌کاربری
node dist/staff-cli.js reset-mfa نام‌کاربری        # کد TOTP جدید
node dist/staff-cli.js grant-refund نام‌کاربری     # فقط پذیرش؛ اجازهٔ تصمیم بازپرداخت
node dist/staff-cli.js revoke-refund نام‌کاربری
```
حساب مدیر را نمی‌توان از پنل غیرفعال کرد. گذرواژهٔ اولیه را پس از اولین ورود تغییر دهید (`reset-password`).

## توالی‌های کاری اصلی
1. **انتشار ظرفیت:** پذیرش → «مدیریت ساعات آزاد» → انتخاب خدمت/شیوه/شعبه/تعرفه. انتشار زمان = رزرو نیست.
2. **رزرو آنلاین:** مراجع وقت را نگه می‌دارد (۱۰–۳۰ دقیقه) ← پیش‌فاکتور ← پرداخت زرین‌پال (درگاه) یا **حضور در شعبه و ثبت نقدی در پذیرش** (رجوع به `CashDesk`).
3. **جلسهٔ آنلاین:** دکمهٔ «ورود به اتاق» فقط برای جلسات قطعی آنلاین همان مراجع، از ۱۵ دقیقه قبل فعال می‌شود.
4. **حضور:** پذیرش → «جلسات» → ثبت حضور/عدم حضور برای هر جلسهٔ گذشته یا جاری.
5. **یادداشت ژورنال:** کاربر عمومی ارسال می‌کند ← «بازبینی یادداشت‌ها» (مدیر) ← انتشار با تصمیم شما. یادداشت‌های نامنطبق منتشر نمی‌شوند.
6. **شهریهٔ دوره:** مراجع پرداخت می‌کند ← در صورت تعارض/بی‌دقیقه‌بودن تراکنش به صف «بازبینی شهریه» می‌رود؛ تصمیم با پذیرش/مدیریت و بدون بازپرداخت خودکار است.
7. **لغو و بازپرداخت:** مراجع درخواست بررسی لغو می‌ثبت کند ← پذیرش تصمیم می‌کند ← اگر مبلغ بازپرداخت تأیید شد، **تأییدکننده نمی‌تواند همان شخص ثبت‌کنندهٔ پیشنهاد باشد**؛ واریز واقعی خارج از سامانه و با مرجع `CASH-/4…` ثبت می‌شود.
8. **پروندهٔ بالینی:** فقط `specialist` در پنل «یادداشت‌های بالینی» برای جلسات قطعی یادداشت ثبت/می‌خواند؛ متن رمزگذاری‌شده در schema جدا ذخیره می‌شود و هر باز شدن در `clinical.access_log` ثبت می‌گردد. پذیرش و مدیریت به متن دسترسی ندارند.
9. **شکایات و بازخورد:** صفحهٔ «تماس با ما» ← «صدای شما شنیده می‌شود» ← پذیرش → «شکایت‌ها و بازخوردها»: تازه → در حال پیگیری → بسته. دادهٔ بالینی دریافت نمی‌شود.

## تنظیمات عمومی سایت (بدون برنامه‌نویس)
پنل مدیر → «تنظیمات سایت» → شمارهٔ تماس، ایمیل، آدرس (فارسی/انگلیسی)، ساعات کار، اینستاگرام/تلگرام/وب‌سایت (https). این اطلاعات در صفحهٔ «تماس با مرکز» نمایش داده می‌شود. خالی بگذارید تا حذف شود. تغییر فقط برای `manager` است.

## عملیات استقرار و امنیت
- متغیرهای محیط:
  - `CLINICAL_KEY` — کلید ۳۲ بایتی base64 (مثلاً با `openssl rand -base64 32`). بدون آن پروندهٔ بالینی با 503 خاموش است و سایت عمومی راه می‌افتد. آن را در secret manager نگه دارید؛ rotation فعلاً دستی است. `PORT`، `PG*`، `PUBLIC_ORIGIN` (مثلاً `https://portal.example.ir`)، `ZARINPAL_MERCHANT_ID` (اختیاری؛ بدون آن پرداخت آنلاین غیرفعال است)، `STAFF_MFA_KEY`، `WEB_ROOT`.
- پس از هر استقرار: `npm run build` در `apps/web` و `apps/api` ← سرویس را با `node apps/api/dist/main.js` (پشت nginx با TLS) بالا بیاورید. curl سربرگ‌ها را چک کنید: `curl -sI https://domain/` باید `Content-Security-Policy` داشته باشد و `X-Powered-By` نداشته باشد.
- پشتیبان‌گیری خودکار پایگاه داده الزامی است؛ `docs/vps-backup-fa.md` را اجرا کنید و بازیابی را روی محیط staging تست کنید.
- لاگ‌ها در سطح `error`/`warn` هستند؛ پایش بیرونی (uptime + دیسک + لاگ ۴xx/۵xx) راه‌اندازی کنید.
- گواهی HTTPS را قبل از راه‌اندازی عمومی تنظیم کنید؛ بدون HTTPS آدرس پرداخت زرین‌پال و کوکی `Secure` درست کار نمی‌کنند.
- این سامانه هنوز فاقد: درگاه پیامک/ایمیل واقعی، ذخیرهٔ فایل چندرسانه‌ای، پروندهٔ بالینی رمزگذاری‌شده (مرحلهٔ بعد)، و تست نفوذ بیرونی است. تا این‌ها نهایی نشوند «راه‌اندازی عملیاتی» اعلام نکنید.
